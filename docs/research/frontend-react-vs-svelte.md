# Frontend research: React 19 stack vs Svelte 5 / SvelteKit

Fact-gathering only. No recommendation. Data collected 2026-09-21.

Context: Go backend with JSON API, SPA embedded in the Go binary, solo/small-team maintainer, data-heavy admin UI (dashboards, charts, poster grids, forms, tables). Handbook stack under comparison: React 19, Vite, React Router, TanStack Query, Zod, Jest 30 + React Testing Library + MSW, ESLint with `react-hooks` and `jsx-a11y`.

Every claim below has a source URL. Items marked **unverified** could not be confirmed from a primary source.

### SPA-only (no SSR) path in SvelteKit

| Fact | Evidence | Source |
|---|---|---|
| Documented SPA mode | Dedicated docs page. Steps: `export const ssr = false;` in root layout, then `adapter-static` with `fallback: '200.html'`. | https://svelte.dev/docs/kit/single-page-apps |
| Caveat stated by Svelte team | "SPA mode has a large negative performance impact by forcing multiple network round trips...before content can be shown." Docs recommend prerendering pages where possible. | https://svelte.dev/docs/kit/single-page-apps |
| `adapter-static` `fallback` option | "the name of the fallback page to be generated by SvelteKit, which is used as the entry point for URLs that have not been prerendered." Note on the option: "This option has large negative performance and SEO impacts. It is only recommended in certain circumstances such as wrapping the site in a mobile app." Output dirs `pages` and `assets` default to `'build'`. | https://svelte.dev/docs/kit/adapter-static |
| `@sveltejs/adapter-static` version | `3.0.10`, peer `@sveltejs/kit: ^2.0.0` | https://registry.npmjs.org/@sveltejs/adapter-static/latest |

Summary of section 1: SPA mode is documented and supported, but the SvelteKit docs describe it as a path with "large negative performance and SEO impacts" and recommend it "only ... in certain circumstances."

## 9. Embedding a Vite-built SPA in a Go binary

| Fact | Evidence | Source |
|---|---|---|
| Vite build output | "simply run the `vite build` command. By default, it uses `<root>/index.html` as the build entry point, and produces an application bundle that is suitable to be served over a static hosting service." | https://vite.dev/guide/build.html |
| `build.outDir` | Type `string`, default `dist`: "Specify the output directory (relative to project root)." | https://vite.dev/config/build-options.html |
| Plain Vite + Svelte | Same as React: output is "HTML, JS, and CSS files inside the `dist` directory". | https://svelte.dev/docs/svelte/getting-started |
| SvelteKit SPA | Requires `@sveltejs/adapter-static` with a `fallback` page (e.g. `200.html`) and `export const ssr = false;` in the root layout; output defaults to `build/` (not `dist/`). The Go server must serve the fallback file for any non-asset route. | https://svelte.dev/docs/kit/single-page-apps ; https://svelte.dev/docs/kit/adapter-static |
| Plain Vite + React | Single `index.html` in `dist/`; the Go server must serve `index.html` for client-side routes. React Router declarative/data modes require no SSR. | https://vite.dev/guide/build.html ; https://reactrouter.com/start/modes |
| Go `embed` | Go standard library `embed` package can embed a directory of static files into the binary. **Unverified in this pass** (Go docs not fetched). | https://pkg.go.dev/embed |
