### Polling interval
- `ActivityMonitor` runs `runMonitoring` on `setInterval`. Defaults: `activeSessionsInterval: 1000` ms when any session has `NowPlayingItem`, `idleInterval: 5000` ms otherwise; both configurable in `app_config.settings.ActivityMonitorPolling`. Starts on idle interval. [ActivityMonitor.js L125-190, L397-426](https://github.com/CyferShepard/Jellystat/blob/main/backend/tasks/ActivityMonitor.js)
- Each tick also does `SELECT * FROM jf_activity_watchdog` (full table read). [ActivityMonitor.js L192](https://github.com/CyferShepard/Jellystat/blob/main/backend/tasks/ActivityMonitor.js)
- With the WebSocket path, "polling" reads a cached `sessionData` array that Jellyfin refreshes every 1500 ms; the REST call is only made on fallback. [sessions-socket-client.js](https://github.com/CyferShepard/Jellystat/blob/main/backend/classes/sessions-socket-client.js)
- Scheduled tasks (minutes): `PartialJellyfinSync` 60, `JellyfinSync` (full) 1440, `Backup` 1440; scheduler loop checks every 10 s; first full sync 10 s after start. [task-scheduler.js L15-30, L146, L158-171](https://github.com/CyferShepard/Jellystat/blob/main/backend/classes/task-scheduler.js)
- History: the 1 s REST poll was blamed for Jellyfin thread-pool starvation (#328) and "might kill Jellyfin server" (#298). Maintainer on #328: "Now Jellystat uses the web socket sessions and only falls back to using the api if it fails to connect ... The main issue was the api call was too heavy on jellyfins server". https://github.com/CyferShepard/Jellystat/issues/328, https://github.com/CyferShepard/Jellystat/issues/298

### Session to playback record (state machine)
Source: [backend/tasks/ActivityMonitor.js](https://github.com/CyferShepard/Jellystat/blob/main/backend/tasks/ActivityMonitor.js), [backend/models/jf_activity_watchdog.js](https://github.com/CyferShepard/Jellystat/blob/main/backend/models/jf_activity_watchdog.js).

1. Identity of a "watch": a session matches a watchdog row when `UserId`, `DeviceId`, and `NowPlayingItemId` match, and for episodes `EpisodeId` also matches. `NowPlayingItemId` is `SeriesId` for episodes, else `Id`. Jellyfin's `Session.Id` is deliberately not used (`// wdData.Id === sessionData.Id &&` is commented out).
2. **Start**: sessions with no watchdog match are inserted into `jf_activity_watchdog` with a fresh `ActivityId` (UUID), `PlaybackDuration: 0`, `ActivityDateInserted: now`, and a snapshot of `PlayState`, `MediaStreams`, `TranscodingInfo`, `PlayMethod`, `RemoteEndPoint`, container (`getSessionsNotInWatchDog`).
3. **Pause / resume**: only rows whose `IsPaused` flag changed are updated ("we return false if playstate didnt change to reduce db writes"). On pause, elapsed seconds are computed as `LastPausedDate - ActivityDateInserted` and added to `PlaybackDuration`; `ActivityDateInserted` is moved to `LastPausedDate`. On resume, `ActivityDateInserted` is reset to now. So `ActivityDateInserted` in the watchdog acts as "segment start", not "play start" (`getSessionsInWatchDog`).
4. **Stop**: watchdog rows with no matching session are "removed". If not paused, `now - ActivityDateInserted` is added to `PlaybackDuration`; the row is deleted from the watchdog and written to `jf_playback_activity` with `Id = ActivityId` (`getWatchDogNotInSessions`).
5. **Merge into a recent record**: before insert, `jf_recent_playback_activity(NEW_WATCH_EVENT_THRESHOLD_HOURS)` returns the latest record per (`NowPlayingItemId`, `EpisodeId`, `UserId`) in the window with `Progress = PlaybackDuration*1e7 / RunTimeTicks`. If a record exists with `Progress <= 80%` and the summed duration would not exceed `RunTimeTicks`, the new segment is added to that record instead of creating a new play. README: "After 1 hour, a new session for the same item will be considered a new watch event." Threshold clamps to 1-12 hours. [ActivityMonitor.js L303-381](https://github.com/CyferShepard/Jellystat/blob/main/backend/tasks/ActivityMonitor.js), [migration 100](https://github.com/CyferShepard/Jellystat/blob/main/backend/migrations/100_jf_recent_playback_activity_runtime_resolution_fix.js), [README](https://github.com/CyferShepard/Jellystat/blob/main/README.md)
6. **Minimum duration**: records with `PlaybackDuration < MINIMUM_SECONDS_TO_INCLUDE_PLAYBACK` (default 1 s) are dropped. [ActivityMonitor.js L12-14, L353-360](https://github.com/CyferShepard/Jellystat/blob/main/backend/tasks/ActivityMonitor.js)
7. **Transcoding**: not tracked as state changes. `PlayMethod`, `TranscodingInfo` and `MediaStreams` are captured once at insert (or when the pause flag flips) and carried into the final record; a mid-play switch from Direct Play to Transcode is not recorded. Source: `jf_activity_watchdog_mapping` snapshot semantics and the `IsPaused`-only update condition in `getSessionsInWatchDog`.
8. **Progress / position**: `PlayState.PositionTicks` is stored only as a JSON snapshot; watch time is derived from wall-clock deltas, not from position ticks. Source: mapping in [jf_activity_watchdog.js](https://github.com/CyferShepard/Jellystat/blob/main/backend/models/jf_activity_watchdog.js).
9. Excluded users are filtered before step 2 (`ExcludedUsers`). [ActivityMonitor.js L161-163](https://github.com/CyferShepard/Jellystat/blob/main/backend/tasks/ActivityMonitor.js)

### Library sync
- Full sync: users -> library folders (minus `ExcludedLibraries`) -> items per library (paged 200, `fields=MediaSources,DateCreated,Genres`) -> seasons/episodes per series -> `jf_item_info` from `MediaSources` -> archive items/seasons/episodes not returned -> `CALL ju_update_library_stats_data()` -> refresh materialized views. [sync.js `fullSync`](https://github.com/CyferShepard/Jellystat/blob/main/backend/routes/sync.js)
- Only items of `Type` in `["Movie", "Audio", "Series"]` are stored as library items, plus `Season` and `Episode` children; other Jellyfin types (Video, Photo, Book, MusicVideo, etc.) are dropped by the filter. This is consistent with #244 ("Mixed" libraries not synced). [sync.js `partialSync` item filters](https://github.com/CyferShepard/Jellystat/blob/main/backend/routes/sync.js), https://github.com/CyferShepard/Jellystat/issues/244
- Partial ("Recently Added") sync pages through the same `/Items?ParentId=` endpoint in blocks of 200, keeps only items whose `DateCreated` is after the last sync date, and stops paging at the first block with no new items. [sync.js `partialSync`](https://github.com/CyferShepard/Jellystat/blob/main/backend/routes/sync.js), [tasks/RecentlyAddedItemsSyncTask.js](https://github.com/CyferShepard/Jellystat/blob/main/backend/tasks/RecentlyAddedItemsSyncTask.js)
- Box-set movies were missed until PR #535 (1.1.12: "Fix library sync missing movies contained in Box Sets"). [Release 1.1.12](https://github.com/CyferShepard/Jellystat/releases/tag/1.1.12)

### Playback Reporting plugin import
Source: [sync.js `syncPlaybackPluginData`](https://github.com/CyferShepard/Jellystat/blob/main/backend/routes/sync.js), [migration 101](https://github.com/CyferShepard/Jellystat/blob/main/backend/migrations/101_ji_insert_playback_plugin_data_to_activity_table.js).
- Manual task only (`GET /sync/syncPlaybackPluginData`); not scheduled.
- Checks `/plugins` for the plugin, then builds `SELECT rowid, * FROM PlaybackActivity` with a `WHERE` that fetches only rows with `DateCreated` older than Jellystat's oldest record or newer than its newest, and `rowid >` the max already imported. Rows are stored raw in `jf_playback_reporting_plugin_data` (`rowid, DateCreated, UserId, ItemId, ItemType, ItemName, PlaybackMethod, ClientName, DeviceName, PlayDuration`).
- `CALL ji_insert_playback_plugin_data_to_activity_table()` copies them into `jf_playback_activity` with `Id = rowid`, `imported = true`, `DeviceId/ApplicationVersion/MediaStreams/TranscodingInfo/PlayState/RemoteEndPoint/ServerId = null`, joining `jf_library_episodes` to resolve episode -> `SeriesId`/`SeasonId` and `jf_library_items` for names.
- Limitation in the procedure: the `WHERE NOT EXISTS (SELECT ... FROM jf_playback_activity WHERE imported=true)` clause means the procedure inserts nothing once any imported row exists. Rows fetched on a second import therefore stay in the staging table. This matches user reports that re-import "says it completed it but nothing gets populated" (#236, #533). https://github.com/CyferShepard/Jellystat/issues/236, https://github.com/CyferShepard/Jellystat/issues/533
- Limitation: rows whose `ItemId` is not in Jellystat's synced items/episodes are skipped (`i."Type" is not null OR ...`), so a library sync must run first, and plays of deleted media are never imported (#249 "Show: SnullEnull" symptom). https://github.com/CyferShepard/Jellystat/issues/249

### Known limitations (source-grounded)
- Postgres-only; SQLite declined (#85). https://github.com/CyferShepard/Jellystat/issues/85
- Single server; no ServerId-based partitioning in queries even though `ServerId` columns exist (migrations 043/044). [migration 043](https://github.com/CyferShepard/Jellystat/blob/main/backend/migrations/043_jf_playback_activity_add_serverid_column.js)
- No backfill from Jellyfin's own ActivityLog (#319 open). https://github.com/CyferShepard/Jellystat/issues/319
- WebSocket session feed depends on a Jellyfin fix: "theres a bug with websockets where it wont send session data unless its for a logged in user" (maintainer, #298), and 404s on `/socket` are reported behind some proxies (#488). https://github.com/CyferShepard/Jellystat/issues/298, https://github.com/CyferShepard/Jellystat/issues/488
- Health check hits `/auth/isConfigured`, which does not verify the DB connection (#445). https://github.com/CyferShepard/Jellystat/issues/445
- Timeline grouping hard-codes a one-month gap (migration 092 comment).

## 6. Gaps and opportunities for a rewrite

Grounded in the issues above and the source.

1. **Server load / collection path.** #298, #328, #66, #344, #369, #115. A rewrite should default to Jellyfin's WebSocket `Sessions` feed with REST fallback (as Jellystat now does for >= 10.11), avoid `SELECT *` on the watchdog every tick, keep in-progress sessions in memory, and bound sync writes so idle instances write nothing (#115). The README lists "Code Optimizations" as required work.
2. **Data-loss on downtime.** #533, #236, #13, #319. Jellystat only records while running; the plugin import has a one-shot procedure (`WHERE NOT EXISTS ... imported=true`) and skips unmatched items. Opportunity: idempotent, incremental import keyed on plugin `rowid`, plus backfill from Jellyfin ActivityLog.
3. **Play-count correctness.** #320, #188, #157, #183, #75, #417. Watch identity ignores Jellyfin `Session.Id` and relies on `UserId + DeviceId + ItemId`; merging uses an 80% progress heuristic and wall-clock deltas. Opportunity: use `PositionTicks` and `PlayState` transitions, explicit segment records, and unit-tested merge rules.
4. **Library coverage.** #34, #244, #403, #184, #535 (box sets). Mixed libraries, grouped movies and box sets were missed; sizes under-reported. Root cause for #244 is visible in source: the sync keeps only `Movie`, `Audio`, `Series`, `Season`, `Episode` types. Bloom closes the playback-reporting part of this gap by resolving the `CollectionFolder` ancestor for every item type, including box sets and playlists, without maintaining a synchronized item catalog. A future catalog still needs a type-agnostic model driven by Jellyfin's `CollectionType`/`IncludeItemTypes`, with size computed from all `MediaSources`.
5. **Multi-server and Emby.** #133, #53. `ServerId` columns exist but nothing partitions by them; README lists multi-server as unfinished.
6. **Access control.** #261, #373, #350. Only a single admin login; "require login off" flow is buggy; SSO token mismatch. Opportunity: roles (admin/viewer), optional Jellyfin-user login, proxy-auth headers.
7. **Deployment.** #85 (SQLite), #148 (PUID/PGID), #327 (DB portability), #445 (healthcheck), #462 (collation warnings), #392 (GHCR). A single Go binary with embedded SQLite (or optional Postgres) removes the largest setup friction Jellystat users report.
8. **Security posture.** Four advisories (three critical SQLi-to-RCE) in 2025-2026 come from string-built SQL in `api.js`/`backup.js`. Parameterized queries only and no shell-outs from request handlers.
9. **Stream-type analytics.** #211, #132, #141. Data is already captured (`PlayMethod`, `TranscodingInfo`, `MediaStreams`) but not charted over time; Direct Stream is conflated with Transcode in the UI.
10. **Notifications.** #6, #177. Webhook code exists but is disabled in `main`; Live TV sessions are visible but not counted.
11. **Stale-media reports.** #26, #409, #172. Requested repeatedly; Jellystat has the data (item list with play counts) but no view.
12. **UI.** #437, #315, #479, README "Responsive UI" under required development.
